# Рынок электроснабжения

Веб-приложение для просмотра и управления данными о потреблении и ценах на электроэнергию в Европейской и Азиатской частях России.

Приложение состоит из двух сервисов:
- **Server** — REST API для работы с данными (`data.csv`), доступен на порту 8888
- **Dashboard** — веб-интерфейс для взаимодействия с API, доступен на порту 8889


## Структура проекта

```
.
├── main.py                  # FastAPI-приложение
├── app.py                   # Streamlit-приложение

```

## Подготовка файла data.csv

Перед запуском убедитесь, что в корне проекта существует файл `data.csv`.  
Файл должен содержать следующие колонки:

| Колонка           | Тип    | Описание                                  |
|-------------------|--------|-------------------------------------------|
| `id`              | int    | Уникальный идентификатор (добавляется автоматически, если отсутствует) |
| `timestep`        | string | Дата и время в формате `YYYY-MM-DD HH:MM` |
| `consumption_eur` | float  | Потребление энергии в Европейской части России (МВт·ч) |
| `consumption_sib` | float  | Потребление энергии в Азиатской части России (МВт·ч) |
| `price_eur`       | float  | Цена в Европейской части России (руб./МВт·ч) |
| `price_sib`       | float  | Цена в Азиатской части России (руб./МВт·ч) |

Пример содержимого `data.csv`:

```csv
id,timestep,consumption_eur,consumption_sib,price_eur,price_sib
1,2006-09-01 00:00,62341.0,17916.0,275.22,0.0
2,2006-09-01 01:00,60000.0,17500.0,260.00,0.0
```

Если файл пуст или отсутствует колонка `id`, приложение добавит её автоматически при первом запросе.

## Сборка и запуск

### 1. Сборка Docker-образов

```bash
docker compose build
```

Эта команда соберёт оба образа: для Server и для Dashboard.

### 2. Запуск контейнеров

```bash
docker compose up -d
```

Флаг `-d` запускает контейнеры в фоновом режиме.

Dashboard дождётся успешного старта Server (healthcheck на '/health') перед запуском.

### 3. Проверка состояния

```bash
docker compose ps
```

Оба сервиса должны быть в состоянии `running`.

### 4. Просмотр логов

```bash
# Все сервисы
docker compose logs -f

# Только FastAPI
docker compose logs -f fastapi

# Только Streamlit
docker compose logs -f streamlit
```

### 5. Остановка

```bash
docker compose down
```

## Использование веб-интерфейса (Dashboard)

Откройте браузер и перейдите по адресу **http://localhost:8889**.

### Индикатор подключения

В верхней части страницы отображается статус соединения с API. Зелёная плашка означает, что API доступен. Если API недоступен, страница остановит работу с сообщением об ошибке.

### Добавление записи

1. В левой колонке заполните форму **«Добавить запись»**:
   - **Время** — дата и время в формате `YYYY-MM-DD HH:MM`, например `2006-09-01 00:00`
   - **Потребление энергии в Европейской части России** — число ≥ 0, например `62341.0`
   - **Потребление энергии в Азиатской части России** — число ≥ 0, например `17916.0`
   - **Цена в Европейской части России** — число ≥ 0, например `275.22`
   - **Цена в Азиатской части России** — число ≥ 0, например `0.0`
2. Нажмите кнопку **«Добавить»**.
3. При успехе появится зелёное уведомление, таблица обновится автоматически.
4. При ошибке валидации появится красное сообщение с описанием проблемы.

### Удаление записи

1. В правой колонке заполните форму **«Удалить запись»**:
   - **id записи** — целочисленный идентификатор из таблицы, например `1`
2. Нажмите кнопку **«Удалить»**.
3. При успехе запись исчезнет из таблицы.
4. Если запись с таким `id` не найдена, отобразится сообщение об ошибке.

### Таблица записей

Под формами отображается таблица со всеми имеющимися записями, отсортированными по времени. Таблица автоматически обновляется после добавления или удаления записей.

### Графики

Под таблицей расположены два интерактивных графика:
- **Потребление электроэнергии** — динамика потребления по двум регионам во времени
- **Цены за электроэнергию** — динамика цен по двум регионам во времени

На графиках можно: увеличивать/уменьшать масштаб колёсиком мыши, перетаскивать видимую область, наводить курсор на точки для просмотра точных значений, скачивать изображение графика кнопкой в правом верхнем углу.

## Использование Server API напрямую

Интерактивная документация Server API доступна по адресу **http://localhost:8888/docs**.

### GET /health

Проверка работоспособности сервиса.

```bash
curl http://localhost:8888/health
# {"status": "ok"}
```

### GET /records

Получить все записи.

```bash
curl http://localhost:8888/records
```

### POST /records

Добавить новую запись.

```bash
curl -X POST http://localhost:8888/records \
  -H "Content-Type: application/json" \
  -d '{
    "timestep": "2006-09-01 02:00",
    "consumption_eur": 58000.0,
    "consumption_sib": 16000.0,
    "price_eur": 250.0,
    "price_sib": 0.0
  }'
```

### DELETE /records/{id}

Удалить запись по идентификатору.

```bash
curl -X DELETE http://localhost:8888/records/1
```

## Обработка ошибок

Оба сервиса настроены на автоматический перезапуск (указано `restart: unless-stopped`) при любых сбоях.

- Server возвращает структурированные JSON-ошибки для всех исключений, включая ошибки валидации (422) и внутренние ошибки сервера (500).
- Dashboard перехватывает все сетевые ошибки и отображает понятные сообщения пользователю, не падая.
- Dashboard не запустится раньше Server из-за указания depends_on с healthcheck, что гарантирует правильный порядок старта.
